What goes where

The overlay needs a desktop; the banner needs only a shell. So the headless servers get the banner alone — which is where it earns its keep, since they are SSH-only.

The address field is drawn in Swiss red in both the overlay and the banner — it is the one value that changes most and the one he most needs to see. Everything else is cream on ink.

03

Linux · terminal banner

raml-banner.sh → /etc/profile.d/. Runs for every interactive login shell, every user.

sudo cp raml-banner.sh /etc/profile.d/00-raml-banner.sh
sudo chmod +x /etc/profile.d/00-raml-banner.sh

It guards on an interactive TTY, so it stays silent during scp, cron jobs and non-interactive SSH commands — where a banner would corrupt output. Facts come from ip route, ip addr and /etc/resolv.conf at run time, so a login immediately after a netplan change shows the new address, which is exactly the feedback you want him to notice.

Truecolor

The colours use 24-bit escapes. Any modern terminal and the Guacamole SSH client render them fine. Over a serial console they degrade to plain text rather than breaking — the layout still holds.

04

Linux · desktop overlay

Conky, drawn onto the desktop top-right, updating every two seconds.

sudo apt install -y conky-all
mkdir -p ~/.config/conky ~/.config/autostart
cp conky-raml.conf   ~/.config/conky/conky.conf
cp raml-conky.desktop ~/.config/autostart/

X11 only — this bites on Ubuntu Desktop

Ubuntu defaults to a Wayland session, where Conky's override window will not paint. At the login screen, click the gear and choose Ubuntu on Xorg. Kali's Xfce is X11 already and needs nothing. If you would rather keep Wayland, the overlay has to be a GNOME extension instead — more moving parts than it is worth for a lab.

Because Conky polls live, there is nothing to refresh on a network change — the panel follows the machine's state on its own.

05

Windows · terminal banner

A PowerShell profile that prints the same block on each new session.

# all users, all hosts (elevated)
Copy-Item Microsoft.PowerShell_profile.ps1 $PSHOME\Profile.ps1

Escapes are written as [char]27 rather than `e, so it renders under both PowerShell 7 and the Windows PowerShell 5.1 that ships on the server. Facts come from Get-NetRoute, Get-NetIPAddress and Get-DnsClientServerAddress, keyed off whichever interface holds the default route.

Also worth setting the Terminal font

The block glyphs need a font that carries them — Cascadia Mono (default in Windows Terminal) is fine. The legacy conhost console also renders them once the codepage is UTF-8, which modern Windows sets by default.

06

Windows · desktop overlay

Two ways. Pick the scripted one for reproducibility; BGInfo if you like its tray refresh.

Scripted — Set-RamlWallpaper.ps1

Generates a branded background at screen resolution, draws the live info panel top-right, sets it as wallpaper. Self-contained, lives in the template, survives a reset. Install once, elevated:

.\Set-RamlWallpaper.ps1 -Install

That copies itself to C:\ProgramData\raml\ and registers a scheduled task with two triggers — at logon, and on the NetworkProfile event that fires when an address changes. So when he reconfigures the NIC, the wallpaper repaints within a second or two without him doing anything.

Alternative — Sysinternals BGInfo

The classic tool. Download BGInfo, add the fields Host Name, IP Address, Default Gateway, DNS Server, MAC Address, drop the raml.ch text at the top, save a .bgi, and run it from a logon task with bginfo.cfg /timer:0 /silent /nolicprompt. Refreshes on demand from the tray. The reason it is the alternative rather than the default: it is a binary you must place in the image, whereas the script is text you can keep in Git alongside everything else.

Why not composite onto a photo

The script paints a solid ink background with a faint watermark rather than compositing onto a wallpaper image, which sidesteps all the resolution and scaling headaches of overlaying text on an arbitrary picture. For a lab machine, legible beats pretty.

Bake it into the templates

Do this once, before sealing each template. Then every clone and every reset comes up already branded — no per-VM work.

The ordering matters: these are the last content changes before the generalize-and-seal steps from the operations sheet.

TemplateAdd before sealing
tpl-ubuntu-serverbanner → /etc/profile.d/
tpl-ubuntu-desktopbanner → /etc/profile.d/; Conky + autostart into /etc/skel/.config/ so every user inherits it
tpl-kalisame as desktop
tpl-win11profile → $PSHOME\Profile.ps1; run Set-RamlWallpaper.ps1 -Install
tpl-winsrv2025profile → $PSHOME\Profile.ps1 (banner only; no desktop overlay needed)

Put the desktop overlay in /etc/skel

Dropping the Conky config and autostart entry into /etc/skel/.config/ before sealing means any user account created later — including his — gets the overlay automatically. Configuring it for one user misses the point the moment a second account appears.

One caveat for the login banner and MOTD

If a template already prints a distro MOTD or its own login art, you will get two banners. On Ubuntu, silence the default set with sudo chmod -x /etc/update-motd.d/* in the template before sealing, so only the raml.ch banner shows.
